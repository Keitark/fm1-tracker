## Test and interpretation

- Separate `display` build profile; no NES machine, cartridge, `iis_open`,
  ALINK ISR or key-scanner entry is linked (checked in the ELF audit).
- Retains the reviewed stock-to-SDK boot bridge, SDK initcall inventory,
  integrity checks and app-core event dispatch. A worker owns the display.
- Uses recovered SPI1 PC7/PC8/PC9/PC10, mux register `0x51020` bit 4,
  CON `0x4021`, BAUD 4 and the same stock panel command table/Y origin 40.
- Does not invent/reset panel GPIOs, enable backlight GPIOs, change clocks,
  initialize audio/scanning, or execute stock application function addresses.
- Red/green/blue horizontal bands, a top strip blinking black/white with the
  millisecond clock, and a bottom white strip after 20 seconds.
- A moving top strip indicates continuing execution/timer/display updates;
  the bottom strip indicates elapsed time, not an integrity-check success flag.
- A blank screen remains ambiguous: early startup, task/timer/clock checks,
  SPI transport, or panel power/reset/backlight. T1 cannot localize those alone.

SPI polling has both a timer deadline and finite iteration bound. Panel delays
have a finite yield-count guard. Rendering yields and services the watchdog.
An error records a RAM diagnostic, stops SPI and idles. There is no live
debugger/USB diagnostic service; post-reset RAM is not runtime evidence.
